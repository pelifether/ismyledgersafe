# Is my Ledger safe?

A one-page site where people post photos of an opened hardware wallet and get a quick visual verdict: does it carry the implanted LTE spyware build that has been found in Ledger devices sold through resellers?

The page shows an exploded isometric Ledger Nano X and an opened Ledger Stax with its back cover beside it (built with the [anatomy](https://skills.wheresryan.sh/anatomy) skill; tabs switch between them, and a result switches to the detected model). The implant parts are drawn in red: the extra board with the nRF9151 LTE module, the second MCU and the eSIM, the U.FL socket, the coax over the battery, the antenna glued in the case, and the power-tap wires. After a check, the figure lights up only the parts that were found.

## How it works

- **`public/index.html`, `public/pt.html`, `public/figure.js`**: generated by `figure/build.mjs` (the figure, its live code and the page, in English and Brazilian Portuguese). Run `npm run build` after changing anything in `figure/`.
- **`middleware.js`**: serves `pt.html` to visitors from Brazil and Portugal (Vercel's `x-vercel-ip-country`), `index.html` to everyone else. `?lang=pt|en` and the footer switch (a `lang` cookie) override it.
- **`public/app.js`**: shrinks each photo in the browser (2000 px long edge, JPEG; this also drops EXIF and GPS), sends up to 6 to `/api/check`, and draws the result and the finding boxes on the photos.
- **`api/check.js`**: sends the photos to Claude with a forensic prompt (`lib/analyze.js`) and a JSON schema. It returns the verdict, the findings with boxes, any antenna SKU, and which photos are missing. **Nothing is stored.** The response carries a signed receipt.
- **`api/share.js`**: only runs when the owner clicks **Share for research** after seeing the result. It checks the receipt (same photos, same verdict, under 6 h old) and saves the photos and `meta.json` (verdict, model, where and when the device was bought) to Vercel Blob under `research/<date>/<id>/`. No IP address or personal data is saved.

Verdicts: `tampered`, `suspicious`, `no_implant_seen` (never "safe": this is a visual check only), `cannot_tell` (it then says which photos to take).

## Deploy on Vercel

1. Import the repo in Vercel. `vercel.json` sets the build command and the output directory.
2. Set the environment variables:
   - `ANTHROPIC_API_KEY`: required.
   - `RECEIPT_SECRET`: a random string of 32+ characters (`openssl rand -hex 32`). It signs receipts and keys the daily visitor hashes. Production refuses to run checks without it.
   - `ANTHROPIC_MODEL` (optional): defaults to `claude-opus-5-5`.
   - `ANTHROPIC_EFFORT` (optional): effort of the fast first pass, default `low`. `CONFIRM_EFFORT` (default `medium`) is the second pass that confirms an all-clear.
3. Storage → create a **Blob** store, choose **private**, and connect it to the project (Production and Preview). OIDC stores give the project `BLOB_STORE_ID` and the SDK signs in by itself; token stores give `BLOB_READ_WRITE_TOKEN`. Either works. If you made a public store, also set `BLOB_ACCESS=public`.
4. In the Anthropic Console, set a monthly spend limit on the workspace the key belongs to. That is the hard backstop.

## Privacy and security

- **Photos**: shrunk and re-encoded in the browser, which drops EXIF and GPS. The server also strips every metadata segment (EXIF, XMP, IPTC, comments) from each JPEG before anything else, and accepts nothing but JPEG.
- **Not stored by default.** `/api/check` sends the photos to Anthropic's API and keeps nothing. Only **Share for research** stores them, in the **private** Blob store (no public URLs), with the verdict and the optional purchase details (source, country code, month). No IP, name, e-mail or device identifier is stored. Anthropic does not train on API data; see its data retention terms for how long API inputs are kept.
- **Logs** record error messages only, never request bodies or photos. Vercel's own request logs (path, IP, time) still exist at the platform level.
- **Usage counters** (`usage/<day>/<visitor>/`) use an HMAC of the IP and the day with `RECEIPT_SECRET`, so they cannot be reversed or linked across days, and earlier days are deleted.
- **Receipts** are HMAC-signed and expire after 6 hours; sharing must send the exact photos that were checked.
- **Page**: no third-party scripts, fonts, analytics or cookies (apart from the optional `lang` choice). A strict Content-Security-Policy allows only the site's own scripts and connections, framing is denied, HSTS is on, and the API refuses cross-site requests.
- **Model output** is shown with HTML escaping; text written inside a photo is treated as data by the prompt.

## Abuse limits

`/api/check` is the only route that spends money. It refuses:
- requests sent from other websites (`Origin` / `Sec-Fetch-Site`);
- bursts: more than 8 checks in 10 minutes from one IP on one function instance;
- more than `DAILY_CHECKS_PER_VISITOR` (default 5) checks a day from one IP, and more than `DAILY_CHECKS` (default 100) a day across the site. These are counted in the Blob store under `usage/<day>/<visitor>/` (the visitor is a salted hash of the IP, never the IP), so they hold across all instances.

Invalid requests are rejected before they count. `GET /api/status` shows whether everything is set up and today's use (the caller's and the site total), without calling the model. For more, add a rate-limit rule on `/api/check` in Vercel → Firewall, and turn on Attack Challenge Mode there if the site is ever flooded.

To see if a deploy is set up: `curl https://ismyledgersafe.vercel.app/api/status` should show `"checker":true,"storage":true`.

`npm run export` downloads all shared submissions to `./research/`. It needs Blob credentials: `vercel env pull` (OIDC: `VERCEL_OIDC_TOKEN` + `BLOB_STORE_ID`) or a `BLOB_READ_WRITE_TOKEN`.

## Local

```sh
npm install
npm run build
MOCK=1 npm run dev                  # canned verdict, no key needed
ANTHROPIC_API_KEY=sk-... npm run dev  # real checks
```

## Updating what it looks for

The reference knowledge is in `SYSTEM` in `lib/analyze.js`: the implant pattern, the antenna SKUs seen so far (`AC-A2205-NANO-X 欧亚版-V1.0`, `AC-A2014-STAX-V1.1`), and the genuine parts of each model. When new variants show up (other regions, other models), add them there. Shared submissions with an `antenna_sku` are a good place to look for them.

The figure kit in `figure/kit/` is from [wheresryan22/anatomy](https://github.com/wheresryan22/anatomy) (MIT).
